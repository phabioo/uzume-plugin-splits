# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

uzume-plugin-splits is the Splits plugin (`uzume.splits`): a split timer for any game with game time and real time, a HUD widget, split lists per game in the plugin store (personal best, best segments), hotkeys, optional autosplit rules (memory conditions; badge and location events through the Pokémon core interface) and a `splits.pb` run event.

## Relation to Uzume

- Plugin for [Uzume](https://github.com/phabioo/uzume) (self-hosted retro gaming platform). Interface: `docs/architecture/12-plugins.md` and `docs/guides/plugin-api.md` in the Uzume repository.
- Plugin API v1 ships with Uzume since 0.11 (`docs/guides/plugin-api.md` there); the store used here ships with Uzume 0.20. Open API items are marked open, never invented.
- Runtime: Lua 5.4 in the Uzume sandbox; UI only as declarative building blocks (no QML).

## Working rules

- Repository language is English: code, comments, UI strings, docs, commit messages and PRs.
- Opus only orchestrates and writes no product code; implementation is done by the Sonnet 5.5 agents in `.claude/agents/`, searching and log reading by the Haiku agent `scout` (alias `haiku`).
- Briefs follow the template in `docs/workflow.md` (which also holds the token-saving rules).
- Opus verifies via `git diff --stat`, a targeted diff and the test result; commit/PR by Opus. One work package per thread, one topic per PR.

## Hard rules

- No ROMs, BIOS, firmware, game files, extracted assets, sprites, maps, text dumps or RAM dumps of real games in the repository or in tests. Tests use only synthetic data generated by code from documented formats.
- Nintendo/Pokémon names may appear as text identifiers only.
- Never put secrets in files, profiles or logs.
- Never overwrite saves silently.

## Languages

- Target versions are the German/EU releases first. Adapters support all language versions of a game where feasible, at least German and English.
- Names of species, moves, items and locations are read from the game at runtime so they appear in the game's language; they are never shipped as tables. Our own data tables are keyed by internal IDs, not names.
- Plugin UI strings come from i18n files (`i18n/`): English is the source, German the first translation.

## Status and commands

- Status: v0.2.0 (comparison against best segments: "sum of best" with its gap to the personal best in the HUD and run tab, per-list comparison choice personal best (default) or best segments for all deltas, issue #9; optional list-wide start and reset rules in the same format as autosplit rules, a reset through the rule never saves a personal best, issue #8; text format headers `@compare`, `@start`, `@reset`; old stored lists get the defaults); v0.1.4 (game time ran at 0:00.00 in the app: it copies memory snapshots, and so delivers `uz.memory.frame()` and ticks, only while a plugin watches a range; the plugin now always watches one byte, and the test mock behaves the same); v0.1.3 (API namespace `uz`, falls back to `fb` on older apps); v0.1.2 (actions that make no sense right now are disabled in the panel and run screen through the uz.ui `disabled` prop of Uzume 0.22, dropped automatically on older apps); v0.1.1 (badge rule through the soullink-core event `badges.changed`; v0.1.0: timer, HUD, rules). Layout and design: `docs/architecture.md`.
- Sources are modules in `src/`; the sandbox has no `require`, so `lua5.4 tools/bundle.lua` generates the committed single `plugin/main.lua` (list new modules in `src/modules.txt`; `--check` fails when stale). Tests: `lua5.4 tests/run.lua` (fake `uz` in `tests/support/uz_mock.lua`, helpers in `tests/support/harness.lua`). Package: `python3 -I tools/package.py [--out DIR] [--tag vX.Y.Z]` builds the unsigned `<id>-<version>.uzplugin` (`--verify FILE` validates). CI (`.github/workflows/ci.yml`) runs bundle check, tests, changelog tool tests and packaging; the manual `release.yml` (input `tag` = `vX.Y.Z`, must equal the manifest version) attaches the package to a GitHub release.
- The SessionStart hook `.claude/hooks/session-start.sh` only prepares cloud sessions (installs `lua5.4` via apt if missing).
